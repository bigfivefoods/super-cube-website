# Multilingual UI (English · isiZulu · Afrikaans)

## Default

**English (`en`)** is the default for all first visits and server-rendered SEO content.

## How it works

- Preference stored in `localStorage` key `sc_locale` (`en` | `zu` | `af`)
- `LocaleProvider` wraps the app
- Language switcher in the **header** (EN / ZU / AF) and **footer**
- Site chrome (nav, footer) + key Learn labels translate immediately
- **Home** hero / proof / buyers / faces and **constructs** hero + face labels translate via `useLocale`
- **FAQ** page (`/faq`) fully translates EN / ZU / AF
- Long theory body copy and LMS course content stay English until full content tracks exist
- URLs stay the same (client locale only) — good for SEO canonicals

## hreflang

`pageMeta()` and root layout emit `alternates.languages` for `en`, `en-ZA`, `zu`, `af`, and `x-default` pointing at the same URL (UI language is client-side). English remains the crawlable default.

## Files

| File | Role |
|------|------|
| `src/lib/i18n.ts` | Dictionaries + helpers (`t` supports `{var}` placeholders) |
| `src/components/LocaleProvider.tsx` | React context |
| `src/components/LanguageSwitcher.tsx` | UI control |
| `src/components/HomeHero.tsx` | Localised home sections |
| `src/components/ConstructsHero.tsx` | Localised constructs hero + jump nav |
| `src/components/FaqContent.tsx` | Localised FAQ |
| `src/app/faq/page.tsx` | FAQ route + FAQPage JSON-LD (English) |

## Adding strings

1. Add the key to the `en` object in `i18n.ts`
2. Add `zu` and `af` translations for the same key
3. Call `const { t } = useLocale();` then `t("your.key")` or `t("key", { n: 2 })` in a client component

## Course content

Lessons, assessments, and video scripts are still English. Use captions and future `/videos/captions/*` for language tracks. Have native speakers review isiZulu and Afrikaans UI copy for school use.
